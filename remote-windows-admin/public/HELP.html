🛠️ Installation & Lifecycle

The gateway is managed by a native PowerShell wrapper script supporting clean install, registration, execution, and removal.

1. Install as elevated Startup Task

Deploys files to C:\Program Files\RemoteWindowsAdmin, opens port 3000 in the firewall, and registers a startup action executing as SYSTEM on system boot:

# Run as Administrator
.\setup.ps1 -Action Install -Passphrase "MySecretPassphrase!" -Port 3000 -SecurityMode safe

2. Diagnostics and Status checks

Checks the Task Scheduler state, current active node.exe PIDs, and displays trailing server log outputs:

.\setup.ps1 -Action Status

3. Other Actions

  • .\setup.ps1 -Action Start: Boots up the background task.
  • .\setup.ps1 -Action Stop: Safely halts the gateway tasks and terminates associated processes.
  • .\setup.ps1 -Action Uninstall: Clears scheduled task, shuts down active processes, removes firewall rules, and deletes installation files.

🛡️ Privileged Access Guardrails

The gateway enforces strict sandboxing to isolate administrative actions and prevent remote execution hijack:

Token Authentication (HMAC-SHA256)

Instead of hardcoded session tokens, users authenticate by posting their passphrase to /api/auth/token to retrieve a JWT session token signed using a random key generated on boot. Tokens automatically expire after 30 minutes.

Safe Mode Whitelisting

Under safe mode, command execution block accepts ONLY Verb-Noun matches present in the allowed list:

  • System Discovery: Get-Service, Get-Process, Get-Volume, Get-Date, Get-CimInstance, Get-EventLog
  • Controls: Start-Service, Stop-Service, Restart-Service, Write-Output
  • Formatting: Select-Object, Where-Object, Measure-Object, Sort-Object, ConvertTo-Json, Out-String

Access Restrictions: Commands utilizing execution redirections, pipelines like Invoke-Expression (iex), Start-Process, or calling shell environments (cmd.exe, bash, wsl) will be immediately blocked and return ERR_BLOCKED_BY_GUARDRAIL.

📸 Screenshot Visual Diagnostics

The gateway uses System.Windows.Forms to capture the primary desktop display as a PNG stream.

Known Screenshot Failure Modes:

  • Timeout Exceeded (ERR_SCREENSHOT_TIMEOUT): Triggered if Windows desktop rendering hangs or takes longer than the 3-second timeout limit.
  • Display Not Ready: Occurs when no physical monitor is attached or during early OS boot phase before a GUI session starts.
  • Permission Denied: Occurs if the Windows service does not run with desktop interaction rights (scheduled startup tasks running as SYSTEM natively have desktop query permissions).

🌐 API Schema Reference & Examples

1. Authentication Handshake

POST/api/auth/token

Exchange passphrase for a token.

# Request payload:
{ "passphrase": "SovereignAdminSecret2026!" }

# Response payload:
{
  "token": "eyJhbGciOiJIUzI1...signature",
  "expires_in": 1800
}

2. Blocked Guardrail Response

POST/api/execute

Attempting to run a blocked cmdlet (e.g. Remove-Item) returns a standardized error envelope:

# Response payload (403 Forbidden):
{
  "error_code": "ERR_BLOCKED_BY_GUARDRAIL",
  "message": "PowerShell block blocked by sandbox guardrails. Input contains unauthorized cmdlets or redirect operators.",
  "details": {
    "command": "Remove-Item C:\\test.txt",
    "mode": "safe"
  },
  "trace_id": "8de209297953bac3",
  "timestamp": "2026-07-15T17:25:41.360Z"
}
