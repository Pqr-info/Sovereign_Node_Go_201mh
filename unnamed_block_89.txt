### Security Checklist

- **Secrets**: store `SESSION_SECRET` and `JWT_SECRET` in a secure vault; rotate regularly.  
- **Session store**: use Redis or a DB-backed store; avoid in-memory store in production.  
- **Cookie flags**: `httpOnly`, `secure`, `sameSite=lax` or `strict` depending on cross-site needs.  
- **Short TTLs**: keep JWT TTL short (e.g., 5 minutes) and issue refresh tokens via a protected refresh endpoint if needed.  
- **Token revocation**: maintain revocation store for JWT signatures and check at handshake time for WebSocket connections.  
- **RBAC**: enforce role checks per route; separate viewer, reviewer, admin roles.  
- **Audit**: record every auth event (login, token issuance, revocation, forced-disconnect) to Jetweb lineage with canonical JSON.  
- **Transport**: require HTTPS and WSS in production.  
- **Rate limiting and brute force protection**: protect login and token endpoints.  
- **CSRF**: for session-based flows, implement CSRF protection on state-changing endpoints. For APIs using JWT in `Authorization` header, CSRF risk is lower.
